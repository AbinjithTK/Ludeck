code actually does on 2026-09-28. Answer the forms from this file, not from memory: a
data safety answer that disagrees with the app is a policy violation.

## 3. App content (Policy, App content)

### Privacy policy
Fill in the two `[DEVELOPER NAME]` and `[CONTACT EMAIL]` placeholders in
`site/privacy.html`, publish `site/` (`docs/SITE.md`), then paste
`https://abinjithtk.github.io/Ludeck/privacy.html`.

### App access
"All or some functionality is restricted." The core app needs no login. Explain:
```
No login is needed to use Ludeck. Publishing an orchard (You > Share your orchard >
Public link) asks the reviewer to sign in with any Google account. Ludeck Pro is
reached from You > Ludeck Pro; licence testers can buy it without being charged.
```

### Ads
**No**, the app contains no ads.

### Content rating (IARC questionnaire)
- Category: **Reference, News, or Educational**. Not a game.
- Violence, sexuality, language, controlled substances, gambling: **No** to all.
  Game cover art is shown as catalogue reference material.
- Users can interact or exchange content: **Yes** (public orchards, reactions,
  follows). Shares location: **No**. Digital purchases: **Yes**.
- Expected result: Everyone / PEGI 3, possibly Teen because of user interaction.

### Target audience and content
- Target age: **18 and over**. Choosing any under-13 band puts the app under the
  Families policy (extra review and SDK requirements), and choosing 13 to 17 adds
  scrutiny of the social features. 18+ is the fast path for this deadline.
- Appeals to children: **No**.

### Data safety
Top level:
- Collects or shares any required user data types: **Yes**
- All user data encrypted in transit: **Yes** (every call is HTTPS)
- Users can request data deletion: **Yes**, **only once in-app account deletion
  exists** (see "Blocking" below). Until it ships, this answer is false.

Data types, each marked **Collected**, **not Shared** (Supabase, RevenueCat, Google
and IGDB are service providers acting for us, which Play does not count as sharing):

| Data type | Required or optional | Purpose | Notes |
|---|---|---|---|
| Personal info: Name | Optional | Account management, App functionality | Google sign-in, only when publishing |
| Personal info: Email address | Optional | Account management | Never shown publicly |
| Personal info: User IDs | Optional | Account management, App functionality | Supabase user id, RevenueCat app user id |
| Financial info: Purchase history | Optional | App functionality | RevenueCat, to grant and restore Pro |
| App activity: Other user-generated content | Optional | App functionality | Published games, tree names, ratings |
| App activity: Other actions | Optional | App functionality | Reactions and follows on public orchards |
| App activity: In-app search history | Required | App functionality | **Processed ephemerally**: sent to the IGDB proxy, not stored |

Not collected: location, contacts, photos, files, device IDs, crash logs,
diagnostics, analytics, advertising ID. The collection itself stays on the device
and is not "collected" in Play's sense.

Links shared into the app are sent to the source site's oEmbed endpoint (YouTube,
TikTok, Vimeo, X, Reddit) directly from the phone to read a title. The privacy
policy states this; Play treats a request to the site the user shared as expected,
not as collection by us.

### Other declarations
- Government app: No. Financial features: No. Health: No. News app: No.
- Account creation: **Yes**, via Google sign-in (OAuth). This is what triggers the
  account deletion requirement.

## 5. Release

1. Testing, Internal testing: upload the first AAB. This unlocks products (section 4).
2. Production: create a release with the final AAB (RevenueCat key, Supabase keys,
   `versionCode` bumped), countries: all, then "Send for review".
3. Publishing overview: turn **Managed publishing off**, so the app goes live the
   moment review passes. "Fully published" is the Shipaton requirement.

## Blocking before production

1. **In-app account deletion.** Google Play requires any app that creates accounts to
   let users delete them inside the app and via a web link. Ludeck has sign-out and
   unpublish, but no delete. It needs a Supabase Edge Function (deletes the caller's
   `auth.users` row; the schema already cascades profiles, trees, games, reactions
   and follows) plus a "Delete account" button. That's Stage 5 work, alongside the
   backend deploy.
2. **What Pro unlocks** (Stage 6). The paywall currently lists features that are not
   built. Selling unbuilt features is misleading-claims territory for review.
3. **Screenshots** (Stage 7).
